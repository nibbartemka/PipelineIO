# PipelineIO

PipelineIO — учебный пайплайн на Python для загрузки, анализа и сохранения постов из [JSONPlaceholder](https://jsonplaceholder.typicode.com/).

Основа пайплана - применения 3 моделей конкурентности:
1. Асинхронность (asyncio)
2. Многопоточность (multithreading)
3. Многопроцессность (multiprocessing)

## Установка и запуск

Требуется Python 3.13 или новее.

```bash
pip install -r requirements.txt
python main.py
```

## Architecture Choices

- **Получение постов по сети — asyncio и aiohttp.** Отправление запросов к API на получение постов - классическая I/O-bound задача. Наиболее оптимальное решение - асинхронность, позволяющая в рамках всего одного потока, обслуживая большое число запросов одновременно (пока ждем ответа по одному запросу, можем переходить к отправке другого) посредством event loop. `asyncio.Semaphore(5)` ограничивает одновременную нагрузку на API, в целях предотвращения блокировки.
- **Обработка постов — multiprocessing.** Подсчёт сложности текста относится к CPU-bound задачам. `ProcessPoolExecutor` распределяет посты между процессами, чтобы вычисления могли выполняться на нескольких ядрах. Применение процессов обусловлено наличием в Python механизма GIL, накладывающего ограничение выполнение байт-кода потоками (в один момент времени, один поток выполняет одну строку байт кода). Для мониторинга используется отдельный процесс и `multiprocessing.Queue`; общий счётчик, реализованный посредством `multiprocessing.Value`, успешно обработанных постов защищён `multiprocessing.Lock`.
- **Сохранение в файл — threading.** Запись файла — I/O-bound задача. Однако для оптимизации выполнения не является возможным применение асинхронности - необходимы потоки. Поэтому эту задачу выполняет пул из четырёх потоков `ThreadPoolExecutor`. `queue.Queue` передаёт обработанные посты воркерам. `threading.Lock` не даёт потокам перемешать записи в `results.log`, а `threading.Event` сообщает потокам о завершении очереди. Отдельный поток периодически сообщает о прогрессе сохранения.
